# Safety and go-live boundary

The hosted Vercel build serves a synthetic-data demo with browser-local storage and an opt-in shared D1 mode. Shared mode creates only the built-in fictional sample, then issues separate 30-day Provider and Client bearer links scoped to that one record and fixed role. Invite links are not authentication or a private portal; anyone holding one can use it. Shared mode blocks record creation/deletion and all PayPal routes. Selected AI source text is sent over HTTPS to the existing temporary authenticated Ollama bridge and may be unavailable when its host sleeps; manual entry remains available. Browser-local PayPal uses Sandbox only. Do not enter real data. JSON/CSV exports are local to the visitor, and JSON exports embed attachments.

The local Node server is a disposable prototype, not a live contract, client portal, legal record, marketplace, or payment service.

1. Keep demo data fictional; do not paste real client agreements, emails, bank details, or cards. Optional attachments are limited to small PDF, PNG, JPEG, TXT, CSV, or Markdown files and stay in browser-local storage; PACT does not scan or verify them. Only the selected source text is sent to the temporary AI bridge when a visitor explicitly requests AI suggestions.
2. In browser-local mode the provider/client role switcher is only a simulator. Shared D1 invite roles are fixed by hashed bearer tokens and expire after 30 days, but there are no accounts, identity checks, revocation, or private-portal protections. Production requires authenticated identity, revocable invitations, party-scoped authorization on every operation, CSRF/session controls, stronger abuse controls, durable backups, managed retention/deletion, monitoring, and independent security review.
3. PayPal credentials must be Sandbox-only. Every standard Orders v2 capture goes to the configured Sandbox merchant account. No provider payout, split settlement, or escrow is implemented. PayPal's production marketplace services require partner approval.
4. The local JSON file store is single-process and not production persistence. Browser-local demo data stays in each browser. Shared D1 stores one fictional sample record per invite set, caps active shares at 128, and cleans expired rows when a new share is created. It is not a production multi-user database or an authenticated service.
5. Optional browser notifications are opt-in, local to one browser, and run only while the app is open. They are not a durable reminder service, email, push notification, or background scheduler.
6. Before any real-user or live-payment use, complete privacy, legal, security, accessibility, reliability, payment-partner, and operational reviews. Never imply that a payment proves delivery or creates escrow.
7. This repository is licensed under the MIT License; see [`LICENSE`](LICENSE) for the terms.

The browser-local PayPal integration is available for judges to inspect, but it is not authenticated: the role selector is a simulator, not an access-control boundary. It is Sandbox-only, rate-limited in memory, limited to USD, and capped by the prototype's amount validation. Shared D1 mode disables PayPal entirely. Use synthetic data and your own Sandbox buyer; no buyer login is provided. Never use saved buyer credentials to approve additional orders without a new, exact order authorization.
